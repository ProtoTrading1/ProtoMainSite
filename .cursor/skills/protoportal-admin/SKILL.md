# Proto Portal Admin Dashboard

The admin panel is a **single React page** (`src/pages/AdminPage.jsx`) — not separate routes per section. All six modules share one component, one sidebar, and overlapping state.

## Entry and access

| Concern | Location |
|---------|----------|
| Host detection | `src/lib/isAdminHost.js` — `protoportal-admin.vercel.app` or `VITE_ADMIN_MODE=true` |
| Routing | `src/Root.jsx` — `adminHost && customer.role === 'admin'` → lazy-loads `AdminPage` |
| Auth Supabase | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` — customers, orders, auth |
| Stock Supabase | `VITE_STOCK_SUPABASE_URL`, `VITE_STOCK_SUPABASE_KEY` — `website_stock`, `main_categories` |

Admin users have `customers.role === 'admin'`. RLS on auth DB uses `is_admin()`. Stock writes use the service-role stock key (bypasses RLS).

## Section map

| Section ID | Label | Key state | Load function |
|------------|-------|-----------|---------------|
| `products` | Product Manager | `productSearchInput`, `productPage`, `productRows`, `catalogTotal` | `loadProducts` → `fetchAdminProductsPage` |
| `specials` | This Week's Specials | `specials` | `fetchSpecials` / `saveSpecials` |
| `archive` | Archive | `archiveSearchInput`, `archivePage`, `archiveRows` | `loadArchive` |
| `reorder` | Reorder Grid | `reorderCategory`, `reorderProducts` | `loadCategoryWorkingSet` → `fetchProductsByMainCategory` |
| `customers` | Customer Management | `customerTab`, `customerSearchInput`, `customerPage` | `loadCustomers` |
| `orders` | Order Requests | `orders`, `orderSearch` | `loadOrders` |

`ADMIN_PAGE_SIZE = 50`. Search inputs are debounced 300ms; page resets synchronously in `onChange` handlers.

## Data layer

**Primary file:** `src/lib/products.js`

- `getAllCachedAdmin()` — session cache of all live `website_stock` rows (~5k products)
- `fetchAdminProductsPage()` — client-side filter + fuzzy search + slice for paging
- `fetchProductsByMainCategory()` — filter by main category slug/label via `matchesMainCategory()`
- `createProduct` / `updateProduct` / `archiveProduct` / `unarchiveProduct` — writes to stock Supabase
- `invalidateAdminCache()` / `invalidateProductCache()` — clear caches after writes

**Product shape** (`adapt()`): DB stores human labels; app adds `category` (slug) and `categoryLabel` (raw text). Slug derived via `labelToSlug()` in `src/lib/taxonomy.js`.

**Search:** `src/lib/fuzzySearch.js` — token/fuzzy match on SKU, barcode, name, description, category path, etc.

## Taxonomy

Two sources for **main categories** (top-level dropdown labels):

1. **`main_categories` table** (stock Supabase) — admin-editable via Reorder Grid → "Manage categories". Migration: `migrations/012_main_categories.sql`. Lib: `src/lib/taxonomyAdmin.js`.
2. **`src/data/categories.json`** — full nested tree (subcategories). Generated by `scripts/generate-categories.mjs` from master workbook. **Not** editable in admin UI yet.

Renaming a main category updates `main_categories.label` **and** bulk-updates `website_stock.category` + `archived_products.category` for matching products.

Subcategory assignment in Product Manager uses dropdowns from `categories.json` only (`childrenAt()` helper in AdminPage).

## Caching and local storage

| Key | Purpose |
|-----|---------|
| `_adminCache` (in-memory) | Full live catalogue for admin session |
| `proto_catalog_v7` (localStorage) | Storefront catalogue cache, 15min TTL |
| `proto_sort_v1` (localStorage) | Reorder Grid drag order per category slug — **browser only**, not synced to DB or other users |

`saveSortOrder` / `updateSortOrder` in products.js are intentional no-ops — `website_stock` has no `sort_order` column.

## Per-section notes

### Product Manager
- Client-side search/filter over cached full catalogue; 50 rows per page
- Stats bar "Live Products" shows `catalogTotal` (full catalogue); filtered count shown when search/filter active
- Product editor modal: SKU, barcode, title, images, category + sub1–sub4
- `createProduct` requires `subcategory_one`

### Reorder Grid
- 3-column drag-and-drop cards per main category
- Quick-edit (image icon): image + description only — not product name or category
- Empty state when no products match category
- Progress bar on first catalogue load

### Archive
- Same paging/search pattern as Product Manager but `archived: true` → `archived_products` table

### Customers
- Tabs: trade requests, approved, premium
- Approve/delete via `src/lib/customers.js`

### Orders
- Client-side search over `fetchAllOrdersAdmin(150)`
- Status updates via `updateOrderAdmin`

### Specials
- Max 10; star toggle from Product Manager
- Persisted via `src/lib/specials.js` API

## Troubleshooting

Read `references/troubleshooting.md` for the full decision tree. Quick hits:

- **Reorder Grid empty but Product Manager shows products** → category slug/label mismatch; check `matchesMainCategory()` and DB `category` text vs `categories.json` id
- **Search returns nothing on page 5+** → page not reset before fetch (fixed: sync reset in onChange)
- **Pagination stays at bottom** → scroll-to-top on `productPage` change
- **Category rename doesn't stick** → run migration 012; verify stock Supabase env vars
- **Reorder order lost on new browser** → expected; order is localStorage only

## When making changes

1. Read surrounding code in `AdminPage.jsx` — match existing patterns (`adm-btn-red`, `adm-modal`, etc.)
2. Writes to products must call `invalidateProductCache()` (or `invalidateAdminCache()` for archive)
3. Category changes must call `invalidateTaxonomyCache()` + product cache invalidation
4. Minimize scope — admin is one large file; don't extract components unless asked
5. Run `npm run build` before claiming done
