# 2026-10-24

Instore customer responses no longer wait for optional catalogue snapshot storage. Authentication, source reads, current image/listing controls, price/stock eligibility, duplicate exclusion, refresh claims, atomic snapshot staging/commit and checkout verification remain in their existing order. Only after the eligible result is sent, Vercel waitUntil retains the same single maintenance attempt for the function lifetime. Failed or slow maintenance cannot replace or delay the HTTP result. No background retries, new cron, schema, settings or stock write is added.

Pinned @vercel/functions 3.10.3 with a lockfile for the supported lifecycle API. Reproduced the previous blocked response using a deliberately unresolved stage RPC and proved the real authenticated handler now completes before that RPC. The same live Instore loading failure occurred on the original and release deployment, so this addresses a demonstrated blocking path rather than claiming the underlying provider/network fault is resolved. Hosted verification remains required; production is held on the original deployment.
