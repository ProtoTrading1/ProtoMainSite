# 2026-09-08

## 10:20 — Standalone school registration site (`schools/`)

**Summary.** New self-contained site where South African schools register for a
Proto Trading Online account. It is a **separate Vercel project** — nothing in
`schools/` is bundled into the main portal, and the portal's build never reads
it. Registrations land in the same Supabase `customers` table as trade
applicants, flagged `is_school`, and are reviewed in the admin dashboard (which
badges them — see Proto_Admin, same date).

**Files affected.**
- `schools/` — new app: `package.json`, `vite.config.js`, `vercel.json`,
  `index.html`, `README.md`, `.gitignore`, `public/proto-trading-online.svg`.
- `schools/src/` — `App.jsx` (the form), `styles.css`, `icons.jsx`, `main.jsx`,
  `lib/schoolFields.js` (field vocabulary + validators),
  `lib/submitSchoolRegistration.js`.
- `schools/api/register-school.js` — new serverless endpoint. Also
  `_rate-limit.js` and `_escape-html.js`, copied from the portal's `api/` since
  the project deploys independently.
- `migrations/067_school_signup.sql` — new. Adds `is_school boolean not null
  default false`, `school_role text`, `supply_needs text[]`, a cardinality
  check and a partial index on `is_school`.
- `eslint.config.js` — ignore nested `**/dist` (the schools build output) and
  give `schools/api/**` Node globals.
- `tests/school-registration.test.js` — new, 7 tests.

**What the form collects.** School name, province, contact name and role, work
email, phone, password, optional supply-need chips, and an explicit
authorisation confirmation. Billing and delivery addresses are deliberately
**not** collected — the admin captures those at approval, so the form stays
short. Layout follows the supplied mockup, with an error summary, per-field
errors, a password reveal toggle, and a sticky "why register" panel added.

**Rules kept.** Schools are never auto-approved and never get an
auto-generated customer code. The service role key is server-side only. The
endpoint is rate limited (8 per IP per 15 min) and has a honeypot field. No
customer WhatsApp messaging.

**Backward compatibility.** `register-school.js` retries the customer insert
with progressively fewer columns, so a registration can never fail merely
because migration 067 has not been applied yet — the account still lands, minus
the school metadata. A failed insert deletes the just-created auth user rather
than leaving an orphan.

## 11:05 — School form: address fields + instant access

**Summary.** Two owner-requested changes to the school registration site.

1. **School address is now collected and required.** New "School address"
   section: street address, suburb, city/town, postal code (4 digits), plus the
   province that was already there. Previously the form deliberately skipped
   addresses and left them to the admin at approval — that is reversed.
2. **Schools now get instant access.** `is_approved: true` on signup, so a
   school can sign in at https://proto.co.za and order immediately instead of
   waiting in the approval queue.

**Files affected.**
- `schools/src/App.jsx` — address fieldset, validation for the four new fields,
  a full-width `Field` variant, and a rewritten success screen ("Your school is
  ready") with a CTA to https://proto.co.za.
- `schools/src/styles.css` — `.field--wide`, `.success-cta`.
- `schools/api/register-school.js` — parses and validates the address; composes
  one address line stored as **both** `company_address` and `delivery_address`,
  plus `street_name` / `suburb` / `city` / `postal_code`. Flips `is_approved`
  to `true`. The admin alert email gains the address row and now says the
  school already has access.
- `schools/README.md` — corrected; it previously stated schools are never
  auto-approved and that addresses are not collected.
- `tests/school-registration.test.js` — updated; new address-storage test.

**Behaviour change worth flagging.** Anyone completing this form now reaches the
wholesale catalogue and trade pricing with no vetting step. That is the
requested design, not an oversight. Customer codes are still never
auto-generated — an admin allocates one later — and the SCHOOL badge still
marks these accounts in Customer Management.

**Verification.**
- `npm run lint` (root) — clean.
- `npm test` (root) — 306 passed, 0 failed.
- `schools/`: `npm run build` — succeeded.
- Ran the built site in headless Chromium: empty submit now lists all 13
  required fields; a filled form posts the address fields in the payload; the
  success screen reads "Your school is ready" with the CTA pointing at
  https://proto.co.za. No JS errors.

**Database status.** No migration needed — every address column
(`company_address`, `delivery_address`, `street_name`, `suburb`, `city`,
`postal_code`) and `is_approved` already exist on `customers`.

**Deployment status.** Pushed to `main`. The schools Vercel project was being
created by the owner at the time of writing; this change is in the code it will
