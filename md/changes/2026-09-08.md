## 10:20 — Standalone school registration site (`schools/`)

**Summary.** New self-contained site where South African schools register for a
Proto Trading Online account. It is a **separate Vercel project** — nothing in
`schools/` is bundled into the main portal, and the portal's build never reads
it. Registrations land in the same Supabase `customers` table as trade
applicants, flagged `is_school`, and are reviewed in the admin dashboard (which
badges them — see Proto_Admin, same date).

**Files affected.**

  `index.html`, `README.md`, `.gitignore`, `public/proto-trading-online.svg`.
- `schools/src/` — `App.jsx` (the form), `styles.css`, `icons.jsx`, `main.jsx`,

  `_rate-limit.js` and `_escape-html.js`, copied from the portal's `api/` since
  the project deploys independently.
- `migrations/067_school_signup.sql` — new. Adds `is_school boolean not null
  default false`, `school_role text`, `supply_needs text[]`, a cardinality
  check and a partial index on `is_school`.
- `eslint.config.js` — ignore nested `**/dist` (the schools build output) and
  give `schools/api/**` Node globals.
- `tests/school-registration.test.js` — new, 7 tests.

**What the form collects.** School name, province, contact name and role, work
email, phone, password, optional supply-need chips, and an explicit
authorisation confirmation. Billing and delivery addresses are deliberately
**not** collected — the admin captures those at approval, so the form stays
short. Layout follows the supplied mockup, with an error summary, per-field
errors, a password reveal toggle, and a sticky "why register" panel added.

**Rules kept.** Schools are never auto-approved and never get an
auto-generated customer code. The service role key is server-side only. The
endpoint is rate limited (8 per IP per 15 min) and has a honeypot field. No
customer WhatsApp messaging.

**Backward compatibility.** `register-school.js` retries the customer insert
with progressively fewer columns, so a registration can never fail merely
because migration 067 has not been applied yet — the account still lands, minus
the school metadata. A failed insert deletes the just-created auth user rather
than leaving an orphan.

## 11:30 — Registered schools land inside the portal, already signed in

**Summary.** On submit, a school is now redirected straight into
https://proto.co.za **already authenticated** — no success screen, no login
form.

**How.** The schools site and the portal are different origins, so the Supabase
session in `localStorage` cannot be shared. The hand-off uses the same mechanism
as Supabase's own magic links:

1. `api/register-school.js` creates the account with the service role key (as
   before), then signs it in with the **public anon key** and returns the
   session.
2. The browser redirects to `${PORTAL_URL}/#access_token=…&refresh_token=…&expires_in=…&token_type=bearer`.
3. The portal's Supabase client has `detectSessionInUrl: true`
   (`src/lib/supabase.js`), so it consumes the fragment, signs the school in and
   strips it from the address bar. `Root.jsx` then routes an approved customer
   to the portal surface.

No `type` parameter is sent: `type=recovery` would send the portal to its
password-reset screen instead. A test asserts it stays absent.

**Files affected.**
- `schools/api/register-school.js` — mints the session; new `PORTAL_URL`
  constant (env-overridable, defaults to https://proto.co.za).
- `schools/src/App.jsx` — redirects with the session fragment via
  `location.replace` (so Back does not return to a submitted form), plus a
  "Taking you to Proto Trading Online…" button state.
- `tests/school-registration.test.js` — two new tests (hand-off, and the
  fallback).
- `schools/README.md` — documents the flow and the new env vars.

**Failure behaviour.** The sign-in is best effort and wrapped in try/catch: the
account is created and approved before it runs. If the anon key is missing or
sign-in errors, the endpoint returns `session: null`, the browser falls back to
the old success screen with a manual sign-in link, and a warning is logged. A
school is never stranded by a failed hand-off.

**New required env var.** `VITE_SUPABASE_ANON_KEY` must now be set on the
schools Vercel project. This reverses earlier advice in this session to delete
that row — at the time nothing used it. It is public by design (already shipped
in the portal's own browser bundle); the *service role* key remains the one that
must never reach the browser.
