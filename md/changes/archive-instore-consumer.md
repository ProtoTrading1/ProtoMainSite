# Archive-routed In-store consumer — paired release hold

Independent companion to the Admin Archive destination review. Based on current storefront main `42db1208e859f8825ab5c3792aff2c43fe72ae96`. Existing Just Added PR271 at `554bbbd89a1b68e9f59c438bd902e2d79d555a5d` is preserved and separate.

Archive-routed products use `image_source_key = archive-review:<durable request ID>`. Only these rows read the review contract's inclusive price, canonical selling unit and cart minimum. Their discovery and checkout never add VAT to an inclusive amount, run the legacy price-fingerprint repair, or silently label a pack EACH. R12.61 remains R12.61 even though the legacy heuristic would treat that value as ex VAT. Missing/mismatched review metadata holds those routed rows while unrelated In-store records retain their existing behavior.

Checkout for these rows verifies the exact POS barcode, explicit inclusive-price provenance, canonical unit and onhand minus booked stock. Requests below the cart minimum, above current availability, or with combined variant quantities exceeding shared base stock stay held. Main SKU/barcode deduplication includes their base identity. The legacy In-store request/packing flow remains unchanged for existing sources.

The established discovery rule is strictly more than ten whole available selling units. Exactly ten remains held. Review decision revisions become part of stored-snapshot and warm-process cache identity. The legacy one-round-trip view remains available when there is no Archive decision; a routed generation bypasses the old view fingerprint and uses the generation-aware snapshot. A changed generation during a live read fails closed and retries on a subsequent request. Existing browser-held collections still revalidate through their established lifecycle, so no claim is made that an already-open tab instantly refreshes after promotion.

This branch adds no migration, credentials, environment changes, source catalogue writes, new-arrival flags or curation. The reviewed Admin schema and separate private-schema access approval are required. Its activation table deliberately remains empty; promotion is held until a paired consumer deployment is reviewed and recorded through a separately authorized action. The trusted POS bridge must expose the exact inclusive website amount and canonical unit first. There is no deployed PostgREST/POS verification in this coding environment.

Local verification: focused contract, discovery, checkout and read-model tests; all669native Node tests; repository lint (zero errors, one pre-existing ProductCard hook warning); production compilation; diff whitespace check. Main and Just Added tabs/UI were not changed by this consumer patch. No production release, customer order, notification or pilot publication occurred.
